# Изменить сетевую функцию Drunkards

Прочитай обязательные [архитектурные](../../rules/architecture.md) и [сетевые правила](../../rules/multiplayer.md). Для мини-игр дополнительно прочитай [их правила](../../rules/minigames.md), для денег и эффектов — [данные и сигналы](../../rules/data-and-signals.md).

1. Проследи существующую цепочку «ввод/сигнал → запрос → владелец состояния → изменение → репликация → локальный отклик». Прочитай скрипт, `.tscn`, spawner/synchronizer и обработку выхода, которые участвуют в этой цепочке.
2. Для каждого затронутого поля установи владельца согласно таблице authority. Отдельно учитывай движение Player, его серверный AppearanceSynchronizer, серверные объекты и локальный PlayerData. Сохраняй владельца при расширении функции.
3. Продолжи ветвление host/client: host вызывает обработчик, client отправляет RPC серверу `1`. Определи отправителя на сервере, проверь его соответствие переданному ID и предусловия именно этой операции. Учитывай локальный вызов с sender `0`.
4. Обнови передачу состояния в существующем механизме. Для поля — пути и режимы SceneReplicationConfig; для события — authority, адресность, call_local и надёжность; для мини-игры — snapshot и обычные обновления. Сохраняй адресную передачу закрытых данных покера.
5. Если создаётся объект, задай имя и начальные данные до добавления, зарегистрируй сцену в правильном MultiplayerSpawner и проверь spawn_path. Учти первоначальный spawn на host и на client, а также позднее подключение.
6. Проследи выход/отключение игрока: освобождение занятости, предметов, очередей, UI и ссылок в затронутом владельце. Сохрани действующее локальное подтверждение/отказ и возврат ресурсов, если они есть у операции.
7. Проверь загрузку Godot, затем сценарий host + отдельный client: действие с каждой стороны, повторный запрос, применимый отказ, подключение после изменения состояния и выход владельца ресурса. Проверяй только сценарии, относящиеся к изменению; сведения о реально выполненной проверке передай пользователю.

Образцы: `Player._enter_tree()` и `scenes/core/player.tscn` — разделение authority; `scripts/levels/bar.gd` — действия с предметами; `scripts/core/seat.gd` — занятость и отказ; `scripts/street/cigarette_machine.gd` — спавн и результат покупки.
