# Изменить мини-игру Drunkards

Обязательные правила: [архитектура](../../rules/architecture.md), [мини-игры](../../rules/minigames.md), [мультиплеер](../../rules/multiplayer.md). Для экономики прочитай [данные](../../rules/data-and-signals.md), для интерфейса — [графику](../../rules/pixel-art.md).

1. Выбери подсистему и прочитай её объект в мире, session/interact, сцену игры и затронутые компоненты. Проследи open/join, назначение slot, snapshot, действие, обновление экрана и leave.
2. Размести изменение в существующем владельце. В покере: Session — состав и сеть, Betting — ставки, Round — фазы и раздача, Evaluator — комбинации, Game и дочерние сцены — отображение. В футболе: Interact — участие/RPC, Game — состояние и gameplay, Ball/Rod/Table/ServeOverlay — их физика и визуал.
3. Добавляя состояние, обнови начальный snapshot, последующие обновления и их применение. Сохрани различие peer ID/slot, наблюдателей, локального игрока и пустых слотов. Для новой сетевой цепочки используй [drunkards-multiplayer-feature](../drunkards-multiplayer-feature/SKILL.md).
4. В покере проверь серверную обработку хода и фаз, защиту переходов после await, адресную передачу закрытых карт и существующий учёт фишек. В футболе проверь управление назначенными штангами, подачу/гол/победу на сервере и коррекцию клиентского мяча.
5. При изменении UI продолжай существующие `.tscn`, сигналы кнопок и процедурный `_draw()` / `@tool`; сохрани `CanvasLayer`, `interact_node`, блокировку мира и существующую семантику закрытия выбранной игры.
6. Проверь затронутый сценарий с host/client, вход посреди игры, выход и повторный вход. Для покера при изменении соответствующей логики проверь readiness, очередность, взнос/выход и приватность карт; для футбола — свободного партнёра, наблюдателя, счёт/подачу и закрытие host. Визуальные правки осмотри на viewport 1280×720.

Продолжай собственный стандарт выбранной игры при каждом изменении. Образцы находятся в её `scripts/minigame/` и `scenes/minigame/`.
